# pg-buddy: PostgreSQL CLI Multi-Tool

**pg-buddy** — это многофункциональный консольный инструмент (CLI) на языке Python, предназначенный для администрирования, мониторинга, тестирования и автоматизации рутинных операций с базами данных PostgreSQL.

Проект разработан в рамках учебной практики и представляет собой «швейцарский армейский нож» для разработчиков и администраторов баз данных. Инструмент позволяет управлять базой данных прямо из терминала без необходимости запуска тяжелых графических клиентов (таких как pgAdmin или DBeaver).

---

## 🎯 Цели и задачи проекта

**Цель:** Разработать консольную утилиту для автоматизации администрирования локальной СУБД PostgreSQL, обеспечивающую удобную работу со схемой данных, импорт/экспорт и генерацию тестовых данных.

**Задачи практики:**
1. Изучить механизмы взаимодействия языка Python с объектно-реляционной СУБД PostgreSQL.
2. Спроектировать расширяемую модульную архитектуру CLI-приложения.
3. Реализовать функции мониторинга состояния БД и выполнения произвольных запросов.
4. Разработать модули переноса данных (импорт/экспорт) в форматы CSV и JSON.
5. Создать генератор реалистичных тестовых данных (seed) для быстрого наполнения таблиц.
6. Реализовать легковесный механизм резервного копирования отдельных таблиц.
7. Провести тестирование разработанного инструмента на локальной СУБД PostgreSQL и составить отчет по практике.

## 🏗️ Архитектура проекта

Приложение строится по модульному принципу для обеспечения простоты поддержки и расширения функционала.

```
pg-buddy/
├── pg_buddy.py          # Главный файл (точка входа, парсинг аргументов CLI)
├── requirements.txt     # Список зависимостей проекта
├── README.md            # Описание проекта и план (этот файл)
├── config/              # Конфигурационные файлы
│   └── connection.json  # Параметры подключения к локальной БД
└── modules/             # Модули с бизнес-логикой
    ├── __init__.py
    ├── db_client.py     # Модуль подключения и общих операций с БД
    ├── status.py        # Модуль мониторинга и сбора статистики
    ├── query.py         # Модуль интерактивного выполнения запросов
    ├── porter.py        # Модуль импорта/экспорта (CSV/JSON)
    ├── seeder.py        # Модуль генерации тестовых данных
    └── backup.py        # Модуль бэкапа и восстановления структуры/данных
```

### Технологический стек:
* **Язык программирования:** Python 3.10+
* **Драйвер СУБД:** `psycopg2-binary` (для подключения к PostgreSQL)
* **Парсер CLI-команд:** `argparse` (встроенная библиотека)
* **Форматирование вывода:** `tabulate` и `rich` (для построения красивых ASCII-таблиц и цветного терминала)
* **Генерация данных:** `Faker` (для наполнения таблиц фейковыми данными)

## 📅 Подробный план разработки (Этапы практики)

### Этап 1: Подготовка окружения и проектирование
* Установка СУБД PostgreSQL на локальный компьютер, создание тестовой базы данных.
* Инициализация Git-репозитория проекта в папке `pg-buddy`.
* Создание виртуального окружения Python (`venv`) и установка базовых библиотек.
* Разработка общей архитектуры CLI: парсинг команд и аргументов (`argparse`), обработка конфигурации подключения.

### Этап 2: Разработка ядра и модуля `status`
* Реализация безопасного класса-клиента для работы с сессиями PostgreSQL с обработкой ошибок подключения.
* Разработка команды `status`: выполнение системных запросов к метаданным Postgres для получения:
  - Версии СУБД и статуса соединения.
  - Размера текущей базы данных.
  - Списка пользовательских таблиц с количеством строк и занимаемым дисковым пространством.

### Этап 3: Разработка модуля интерактивных запросов `query`
* Реализация команды `query`, позволяющей:
  - Выполнять одиночные SQL-запросы, переданные в качестве аргументов.
  - Форматировать результаты выборки (`SELECT`) в красивые текстовые таблицы прямо в консоли.
  - Запускать пакетные скрипты из внешних `.sql` файлов.

### Этап 4: Разработка модуля импорта/экспорта `export` и `import`
* Реализация экспорта данных: извлечение данных из указанной таблицы или результата SQL-запроса и сохранение в файлы CSV или JSON.
* Реализация импорта данных: чтение файлов CSV/JSON и добавление записей в таблицы БД с валидацией структуры и типов.

### Этап 5: Разработка модуля генерации тестовых данных `seed`
* Реализация автогенератора записей с использованием библиотеки `Faker`.
* Поддержка стандартных типов полей: имена, email, телефоны, адреса, случайные числа, даты, логические значения.
* Реализация пакетной вставки (bulk insert) для обеспечения высокой скорости работы модуля.

### Этап 6: Разработка модуля резервного копирования `backup`
* Создание алгоритма извлечения структуры таблицы (DDL-код `CREATE TABLE`).
* Экспорт данных таблицы в формат набора инструкций `INSERT INTO`.
* Сохранение структуры и данных в один `.sql` файл, пригодный для быстрого восстановления через `psycopg2` или стандартный терминал.

### Этап 7: Интеграционное тестирование и документирование
* Проведение комплексного тестирования всех модулей на реальных локальных таблицах.
* Обработка исключений (неверный пароль, отсутствие таблицы, нарушение ограничений целостности данных).
* Написание финального отчета по практике, демонстрация работы утилиты руководителю.

## 🚀 Быстрый старт (Проектный шаблон)

Для запуска утилиты после реализации потребуется:

1. **Создать виртуальное окружение и установить зависимости:**
   ```bash
   python -m venv venv
   source venv/bin/activate  # На Windows: venv\Scripts\activate
   pip install psycopg2-binary tabulate Faker rich
   ```
2. **Настроить конфигурацию подключения в `config/connection.json`:**
   ```json
   {
     "host": "localhost",
     "port": 5432,
     "database": "pg_buddy_db",
     "user": "postgres",
     "password": "your_secure_password"
   }
   ```
3. **Пример использования:**
   ```bash
   python pg_buddy.py status
   ```
